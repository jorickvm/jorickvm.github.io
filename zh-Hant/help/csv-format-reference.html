CSV 格式參考

只有 Country（國家）欄位是必填。AtlasDays 依標題名稱辨識支援的欄位，所以欄位的先後順序不影響結果。

建議的標題列

Country,State,Start Date,End Date,Purpose,Notes

  • Country：英文國家名稱、ISO 兩碼代碼，或可辨識的常見別名。
  • State：選填，美國的州名、郵政縮寫，或 US-CA 這類 ISO 行政區代碼。
  • Start Date / End Date：精確日期、年份，或依下列規則留空。
  • Purpose：Tourism（觀光）、Business（商務）、Medical（醫療）、Transit（轉機）或 Personal（個人）；除 Transit 以外的目的可以用逗號分隔並列多個。
  • Notes：選填的文字。

日期格式

精確日期

兩個日期欄位都使用 yyyy-mm-dd。只有行程還在進行時，才把 End Date 留空。

年份

在 Start Date 填入四位數的年份。End Date 可以填年份，也可以留空表示同一年。跨越多年的區間，會變成每年一筆僅年份的紀錄。

完全沒有日期

兩個日期欄位都留空。該國家會保存成沒有日期的到訪：計入造訪過的地點，但完全不計入天數總計，報表中會標示為日期不明。這種紀錄只能透過 CSV 匯入建立。

美國州別的資料列

只有美國的行程才使用 State。如果一次美國行程去了好幾個州，而且需要州層級的紀錄，就每個州各寫一列。只填國家的美國資料列一樣有效，可用於國家層級的記錄。

轉機（Transit）

沒有實際入境時，在 Purpose 填入 Transit。Transit 具有排他性：不要和 Tourism、Business 或其他目的並用。

範例

Country,State,Start Date,End Date,Purpose,Notes
France,,2026-03-01,2026-03-05,Tourism,
United States,CA,2026-04-10,2026-04-15,Business,Conference
Japan,,2024,,Tourism,Dates not known
United Arab Emirates,,2026-05-01,2026-05-01,Transit,Airport connection

分隔符號與引號

AtlasDays 會從標題列判斷檔案是以逗號、分號還是 Tab 分隔。欄位內含分隔符號或換行時，請依一般的 CSV 規則加上引號。

某個值無法辨識時

請改用 ISO 國家代碼、明確的英文國家名稱、ISO 日期格式，以及標準的美國州名或代碼。保留原本的列號，方便和匯入確認畫面對照。
