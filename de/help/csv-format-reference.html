AtlasDays / Hilfe

CSV-Format: Referenz

Eine Datei braucht für jede Zeile ein Land und für die Reisen, die in die Tagessummen einfließen sollen, Reisedaten. AtlasDays findet Spalten anhand ihres englischen Spaltenkopfs, die Reihenfolge der Spalten spielt also keine Rolle, und es erkennt die Namen, die andere Reise-Apps verwenden. Die Schritte zum Importieren stehen unter CSV-Import.

Spalten

Empfohlene Kopfzeile für eine Datei, die du selbst schreibst: Country,State,Start Date,End Date,Purpose,Notes. Bei den Spaltenköpfen wird Groß- und Kleinschreibung nicht beachtet, und ein Unterstrich zählt als Leerzeichen. Nicht erkannte Spalten wie Days werden ignoriert. Bedeuten zwei Spalten dasselbe, wird die erste verwendet; eine Spalte, die genau Purpose heißt, hat aber immer Vorrang.

Country
Wird auch aus Countries, Country Name, Country/Region, Nation, Place oder Destination gelesen. Ländername auf Englisch oder in der App-Sprache, ISO-Ländercode aus zwei Buchstaben oder ein gängiger Alias wie USA, UK oder Holland. Ein Alias, der zwei Orte meinen könnte, wird abgelehnt.
Country Code
Wird auch aus ISO, ISO Code, ISO2, Alpha-2, Code oder CC gelesen. Ein Code aus zwei Buchstaben. Enthält eine Datei beides, wird der Code verwendet und der Name ignoriert.
State
Wird auch aus US State, State/Province, Province, Region oder Subdivision gelesen. Nur für Reisen in die Vereinigten Staaten: Name des Bundesstaats, zweistellige Postabkürzung oder ISO-Code wie US-CA. Der District of Columbia wird akzeptiert.
Start Date
Wird auch aus Start, Arrival, Arrival Date, Entry, Date From, Begin, Check-in und ähnlichen Namen gelesen. Siehe Datumsformate unten.
End Date
Wird auch aus End, Departure, Departure Date, Exit, Date To, Until, Check-out und ähnlichen Namen gelesen. Leer bedeutet: noch unterwegs (bei genauem Beginn) oder dasselbe Jahr (bei Beginn mit Jahreszahl).
Purpose
Wird auch aus Reason, Type, Trip Type, Category oder Visit Type gelesen. Personal, Business, Study oder Transit, Groß- und Kleinschreibung egal. Werte außer Transit kombinierst du mit Kommas in Anführungszeichen, etwa "Business, Personal", oder mit ; oder /. Gängige Wörter werden zugeordnet: Work wird Business, Holiday oder Vacation wird Personal, School wird Study, Layover wird Transit. Andere Werte bleiben als Zeile Zweck: in den Notizen der Reise erhalten.
Notes
Wird auch aus Note, Notes (optional), Comment, Description, Remarks oder Memo gelesen. Freitext.
City
Wird auch aus Cities oder Town gelesen. Wird den Notizen der Reise hinzugefügt.
Is Current
Wird auch aus Current oder Ongoing gelesen. Yes, True oder 1 lässt die Reise ohne Enddatum weiterlaufen, egal was beim Enddatum steht.
Work Days, Personal Days
Werden verwendet, wenn es keine Spalte Purpose gibt: Eine Reise mit nur Arbeitstagen wird Business, mit nur privaten Tagen Personal. Eine Reise mit beidem erhält die Notiz Geschäftlich und privat.
Transit
Wird auch aus Layover oder Airside gelesen. Wird nur gelesen, wenn es keine Spalte Purpose gibt. Yes, Y, True oder 1 markiert Transit; No, N, False, 0 oder leer nicht.
Start Year, End Year
Ältere Spalten. Vierstellige Jahreszahlen, die verwendet werden, wenn die Datumszellen kein Jahr enthalten. Lassen sich in derselben Zeile nicht mit genauen Reisedaten kombinieren.

Die Bildschirmfotos zeigen die App auf Englisch. Im Text stehen die Namen so, wie du sie auf Deutsch siehst.

Dateiaufbau

AtlasDays unterscheidet drei Aufbauarten anhand der Spalten:

  • Eine Zeile pro Reise: ein Land mit Start- und Enddatum. So sind die Vorlage, ein Tabellen-Export von AtlasDays und die meisten Reise-Apps aufgebaut.
  • Eine Zeile pro Tag: eine Spalte Date (oder Day) und ein Land. Aufeinanderfolgende Tage im selben Land werden zu einer Reise, und ein fehlender Tag beendet sie. Ist der letzte Tag heute oder gestern, läuft die Reise ohne Enddatum weiter. Die Kopfzeile darf fehlen, wenn die erste Zeile ein Datum und ein Land enthält. Für einen Tag in zwei Ländern trennst du sie mit einem senkrechten Strich, etwa France|Germany: Beide erhalten den Tag. Bundesstaaten und Städte lassen sich genauso aufführen.
  • Eine Zeile pro Grenzübertritt: eine Spalte Date mit den Ländern From und To. Jeder Tag eines Grenzübertritts zählt für beide Länder, und du bleibst bis zum nächsten Grenzübertritt im Land aus To. Der letzte Aufenthalt läuft ohne Enddatum weiter. Zeilen mit Grenzübertritten lassen sich auch in eine Tag-für-Tag-Datei mischen.

In einer Datei ohne Spalte Date werden From und To als Start- und Enddatum einer Reise gelesen.

Neben yyyy-mm-dd liest AtlasDays:

  • Das Jahr zuerst, mit Schrägstrichen oder Punkten, etwa 2026/03/01 oder 2026.03.01. Eine Uhrzeit nach dem Datum, etwa 2026-03-01 22:47 oder 2026-03-01T22:47:00Z, wird ignoriert.
  • Englische Monatsnamen und Abkürzungen, etwa 1 Mar 2026, Mar 1, 2026 oder 01-Mar-26.
  • Den Tag oder den Monat zuerst, etwa 01/03/2026 oder 03/01/2026, mit vierstelliger oder zweistelliger Jahreszahl. Weil 01/03 beides sein kann, liest AtlasDays diese Angaben nur, wenn ein Datum in der Datei einen Tag über 12 hat, der die Reihenfolge verrät. Andernfalls werden diese Zeilen mit dem Hinweis übersprungen, dass unklar ist, was Tag und was Monat ist.

Eine zweistellige Jahreszahl wird als 20xx gelesen, wenn das höchstens 10 Jahre in der Zukunft liegt, sonst als 19xx. Jahreszahlen müssen zwischen 1900 und acht Jahren nach dem aktuellen Jahr liegen. Jahreszahlen und genaue Reisedaten lassen sich in einer Zeile nicht mischen. Reisen vom Typ Nur Jahr und Reisen ohne Reisedaten zählen für besuchte Orte und die Karte, nie aber für die Tageszählung oder Tracker. Eine Reise ohne Reisedaten lässt sich nur über den CSV-Import anlegen.

Sonderfälle

  • US-Bundesstaaten. Nimm eine Zeile pro Bundesstaat, wenn ein US-Besuch mehrere Bundesstaaten umfasste. Eine einfache Zeile mit United States ist für die Erfassung auf Länderebene gültig. Ein Name eines Bundesstaats in der Spalte Country (California, US-CA) ergibt ebenfalls eine US-Reise, ebenso ein leeres Country mit gültigem State. Zweistellige Codes, die zugleich Ländercodes sind, etwa CA, bleiben Länder. Ohne Pro werden Bundesstaaten-Zeilen als gewöhnliche Reisen in die Vereinigten Staaten importiert.
  • Transit. Trag Transit bei Purpose ein, wenn du nicht in das Land eingereist bist. Transit schließt andere Werte aus: Steht er neben einem anderen Zweck, bleibt nur Transit erhalten.
  • Trennzeichen und Anführungszeichen. Komma, Semikolon und Tabulator werden anhand der Kopfzeile erkannt. Setz Felder in Anführungszeichen, die das Trennzeichen oder einen Zeilenumbruch enthalten.

Wenn ein Wert nicht erkannt wird

Verwende einen ISO-Ländercode, Datumsangaben im Format yyyy-mm-dd und einen gängigen Namen oder Code eines US-Bundesstaats. Eine aus einer Tabellenkalkulation in einer anderen Sprache exportierte Datei kann übersetzte Spaltenköpfe tragen, die nicht erkannt werden: Benenne sie in die oben genannten englischen Spaltenköpfe um. Für eine Datei, die AtlasDays gar nicht lesen kann, gibt dir CSV mit KI erstellen auf dem Importbildschirm einen Prompt zum Umwandeln.
