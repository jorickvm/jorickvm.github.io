AtlasDays / 說明中心

CSV 格式參考

檔案的每一列都需要國家；要計入天數總計的行程，還需要日期。AtlasDays 依英文標題名稱辨識欄位，所以欄位的先後順序不影響結果，也能辨識其他旅行 App 使用的欄位名稱。匯入的步驟請見CSV 匯入。

欄位

自行製作檔案時建議的標題列：Country,State,Start Date,End Date,Purpose,Notes。標題名稱不分大小寫，底線視同空格。無法辨識的欄位（例如 Days）會被忽略。若有兩個欄位意思相同，則採用第一個，但名稱正好是 Purpose 的欄位一律優先。

Country
也會從 Countries、Country Name、Country/Region、Nation、Place 或 Destination 讀取。可填英文或 App 語言的國家名稱、ISO 兩碼代碼，或常見別名，例如 USA、UK 或 Holland。可能指兩個地方的別名會被拒絕。
Country Code
也會從 ISO、ISO Code、ISO2、Alpha-2、Code 或 CC 讀取。兩碼代碼。檔案同時有國家名稱與代碼時，會採用代碼並忽略名稱。
State
也會從 US State、State/Province、Province、Region 或 Subdivision 讀取。僅限美國行程：可填州名、兩碼郵政縮寫，或 US-CA 這類 ISO 代碼。也接受哥倫比亞特區（District of Columbia）。
Start Date
也會從 Start、Arrival、Arrival Date、Entry、Date From、Begin、Check-in 等類似名稱讀取。請見下方的日期格式。
End Date
也會從 End、Departure、Departure Date、Exit、Date To、Until、Check-out 等類似名稱讀取。留空表示停留中（開始日期為精確日期），或同一年（開始日期為年份）。
Purpose
也會從 Reason、Type、Trip Type、Category 或 Visit Type 讀取。Personal（個人）、Business（商務）、Study（就學）或 Transit（轉機），不分大小寫。Transit 以外的多個值可放在引號內以逗號分隔，例如 "Business, Personal"，也可以用 ; 或 / 分隔。常見字詞會自動對應：Work 為 Business，Holiday 或 Vacation 為 Personal，School 為 Study，Layover 為 Transit。其他值會以一行 目的： 保留在行程的備註中。
Notes
也會從 Note、Notes (optional)、Comment、Description、Remarks 或 Memo 讀取。自由文字。
City
也會從 Cities 或 Town 讀取。會加入行程的備註。
Is Current
也會從 Current 或 Ongoing 讀取。Yes、True 或 1 會讓行程保持停留中，不論結束日期為何。
Work Days、Personal Days
在沒有 Purpose 欄時使用：只有工作天的行程會成為 Business，只有個人天的行程會成為 Personal。兩者都有的行程會加上 商務與個人 備註。
Transit
也會從 Layover 或 Airside 讀取。只有在沒有 Purpose 欄時才會讀取。Yes、Y、True 或 1 代表轉機；No、N、False、0 或留空則不是。
Start Year、End Year
舊版欄位。四位數的年份，用於日期欄位沒有年份的情況。同一列不能與精確日期並用。

檔案版面

AtlasDays 會依欄位分辨三種版面：

  • 每列一個行程：一個國家，加上開始與結束日期。範本、AtlasDays 試算表匯出檔，以及大多數旅行 App 都採用這種版面。
  • 每列一天：一個 Date（或 Day）欄位加上國家。在同一國家的連續日期會合成一個行程，中間缺一天，行程就結束。若最後一天是今天或昨天，該行程會保持停留中。第一列含有日期與國家時，可省略標題列。某天身處兩個國家時，請用直線分隔，例如 France|Germany，兩國都會計入當天。州與城市也可以用同樣方式列出。
  • 每列一次跨境：一個 Date 欄位，加上 From 與 To 國家。每個跨境日同時計入兩國，而在下次跨境之前，都會視為停留在 To 國家。最後一段停留會保持停留中。跨境資料列也可以混入逐日檔案中。

在沒有 Date 欄位的檔案中，From 與 To 會被讀取為行程的開始與結束日期。

日期格式

Start DateEnd Date結果
2026-03-012026-03-05精確日期的行程。同一天的行程，日期要寫兩次。
2026-03-01留空沒有結束日期、停留中的行程。
2019留空該年的僅年份行程。
20182019涵蓋 2018 至 2019 年的一筆僅年份行程。
留空留空沒有日期的行程。

除了 yyyy-mm-dd，AtlasDays 也能讀取：

  • 年份在前、以斜線或句點分隔的日期，例如 2026/03/01 或 2026.03.01。日期後面的時間，例如 2026-03-01 22:47 或 2026-03-01T22:47:00Z，會被忽略。
  • 英文月份名稱與縮寫，例如 1 Mar 2026、Mar 1, 2026 或 01-Mar-26。
  • 日在前或月在前的日期，例如 01/03/2026 或 03/01/2026，年份可為四位數或兩位數。由於 01/03 兩種讀法都有可能，只有在檔案中某個日期的日大於 12、能看出順序時，AtlasDays 才會讀取這類日期；否則這些資料列會以無法分辨日與月略過。

兩位數的年份若讀為 20xx 時最多在 10 年後，就讀為 20xx，否則讀為 19xx。年份必須介於 1900 與目前年份之後第 8 年之間。同一列不能混用精確日期與年份值。僅年份的行程與沒有日期的行程，會計入造訪過的地點與地圖，但不會計入天數或追蹤器。沒有日期的行程只能透過 CSV 匯入建立。

特殊情況

  • 美國各州。一次美國行程去了好幾個州時，每個州各寫一列。只寫 United States 的資料列有效，可用於國家層級的追蹤。在 Country 欄填州名（California、US-CA）同樣會得到美國行程，Country 留空但 State 有效時也一樣。同時也是國家代碼的兩碼代碼，例如 CA，仍視為國家。沒有 Pro 時，州別資料列會匯入為一般的美國行程。
  • 轉機。沒有實際入境時，在 Purpose 填入 Transit。Transit 具有排他性：若與其他目的並用，只會保留 Transit。
  • 分隔符號與引號。逗號、分號與 Tab 會從標題列自動判斷。內含分隔符號或換行的欄位，請加上引號。

若沒有任何一列可以匯入，預覽不會開啟，而是由找不到行程說明原因，例如AtlasDays 在這個檔案中找不到國家欄位。

某個值無法辨識時

請使用 ISO 國家代碼、yyyy-mm-dd 日期，以及標準的美國州名或代碼。以其他語言的試算表匯出的檔案，標題可能被翻譯而無法辨識，請改回上述英文標題。若 AtlasDays 完全無法讀取檔案，可使用匯入畫面上的用 AI 建立 CSV，取得轉換檔案用的提示詞。
