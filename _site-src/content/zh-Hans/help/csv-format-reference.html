CSV 格式参考

文件的每一行都需要国家；要计入天数总计的行程还需要日期。AtlasDays 按英文表头名称识别列，所以列的先后顺序不影响结果，它也能识别其他旅行 App 使用的列名。导入步骤见 CSV 导入。

列

自己编写文件时推荐的标题行：Country,State,Start Date,End Date,Purpose,Notes。表头名称不区分大小写，下划线视同空格。无法识别的列（例如 Days）会被忽略。两列含义相同时采用第一列，但名称恰好为 Purpose 的列始终优先。

Country
也会从 Countries、Country Name、Country/Region、Nation、Place 或 Destination 读取。英文或 App 语言的国家名称、ISO 两位字母代码，或常见别名，例如 USA、UK、Holland。可能指向两个地方的别名会被拒绝。
Country Code
也会从 ISO、ISO Code、ISO2、Alpha-2、Code 或 CC 读取。两位字母代码。文件中同时有国家名称和代码时，使用代码，忽略名称。
State
也会从 US State、State/Province、Province、Region 或 Subdivision 读取。仅限美国的行程：州名、两位字母的邮政缩写，或 US-CA 这类 ISO 代码。哥伦比亚特区也可以。
Start Date
也会从 Start、Arrival、Arrival Date、Entry、Date From、Begin、Check-in 等类似名称读取。见下面的日期格式。
End Date
也会从 End、Departure、Departure Date、Exit、Date To、Until、Check-out 等类似名称读取。留空表示停留中（开始日期确切时），或与开始年份相同（开始为年份时）。
Purpose
也会从 Reason、Type、Trip Type、Category 或 Visit Type 读取。Personal、Business、Study 或 Transit，不区分大小写。Transit 以外的多个值可以放在引号内用逗号分隔，例如 "Business, Personal"，也可以用 ; 或 / 分隔。常见词语会自动对应：Work 为 Business，Holiday 或 Vacation 为 Personal，School 为 Study，Layover 为 Transit。其他值会作为一行 目的： 保留在行程的备注中。
Notes
也会从 Note、Notes (optional)、Comment、Description、Remarks 或 Memo 读取。自由文本。
City
也会从 Cities 或 Town 读取。添加到行程的备注中。
Is Current
也会从 Current 或 Ongoing 读取。Yes、True 或 1 会让行程保持停留中，无论结束日期是什么。
Work Days、Personal Days
在没有 Purpose 列时使用：只有工作日的行程记为 Business，只有个人日的行程记为 Personal。两者都有的行程会加上 商务和个人 备注。
Transit
也会从 Layover 或 Airside 读取。只有在没有 Purpose 列时才会读取。Yes、Y、True 或 1 表示转机；No、N、False、0 或留空则不是。
Start Year、End Year
旧版的列。四位数的年份，在日期单元格里没有年份时使用。同一行里不能与确切日期并用。

文件布局

AtlasDays 根据列来区分三种布局：

  • 每行一个行程：一个国家，加上开始日期和结束日期。模板、AtlasDays 电子表格导出文件和大多数旅行 App 都采用这种布局。
  • 每行一天：一个 Date（或 Day）列和一个国家。同一国家的连续日期会合成一条行程，中间缺一天，行程就结束。最后一天是今天或昨天时，这条行程会保持停留中。第一行包含日期和国家时，可以省略标题行。某天身在两个国家时，用竖线分隔，例如 France|Germany，两个国家都会计入这一天。州和城市也可以这样列出。
  • 每行一次跨境：一个 Date 列，加上 From 和 To 国家。每个跨境日同时计入两个国家，直到下一次跨境之前，都视为停留在 To 国家。最后一段停留会保持停留中。跨境的数据行也可以混在逐日文件里。

在没有 Date 列的文件中，From 和 To 会被读作行程的开始日期和结束日期。

日期格式

Start DateEnd Date结果
2026-03-012026-03-05确切日期的行程。当天往返的行程，两个日期填同一天。
2026-03-01留空停留中的行程，没有结束日期。
2019留空该年的仅年份行程。
20182019一条涵盖 2018 至 2019 年的仅年份行程。
留空留空没有日期的行程。

除了 yyyy-mm-dd，AtlasDays 还能读取：

  • 年份在前、用斜线或点分隔的日期，例如 2026/03/01 或 2026.03.01。日期后面的时间，例如 2026-03-01 22:47 或 2026-03-01T22:47:00Z，会被忽略。
  • 英文月份名称及缩写，例如 1 Mar 2026、Mar 1, 2026 或 01-Mar-26。
  • 日在前或月在前的日期，例如 01/03/2026 或 03/01/2026，年份可以是四位数或两位数。由于 01/03 两种读法都有可能，只有当文件中某个日期的日大于 12、能看出顺序时，AtlasDays 才会读取这类日期；否则这些行会以无法分辨日和月跳过。

两位数的年份如果读作 20xx 后最多在 10 年之后，就读作 20xx，否则读作 19xx。年份必须在 1900 年到当前年份之后八年之间。同一行里不能混用确切日期和年份值。仅年份的行程和没有日期的行程会计入到访过的地点和地图，但永远不计入天数或追踪器。没有日期的行程只能通过 CSV 导入创建。

特殊情况

  • 美国各州。一次赴美去了好几个州时，每个州各占一行。只填 United States 的数据行同样有效，可用于国家一级的记录。在 Country 列里填州名（California、US-CA）也会得到美国行程；Country 留空而 State 有效，效果相同。同时也是国家代码的两位字母代码，例如 CA，仍按国家处理。没有 Pro 时，州的数据行会作为普通的美国行程导入。
  • 转机。没有实际入境时，在 Purpose 填入 Transit。Transit 具有排他性：与其他目的同时出现时，只保留 Transit。
  • 分隔符与引号。逗号、分号和制表符会从标题行自动判断。字段内含分隔符或换行时，请加引号。

如果没有任何一行可以导入，预览不会打开，而是由未找到行程说明原因，例如AtlasDays 在这个文件中找不到国家列。

如果某个值无法识别

请使用 ISO 国家代码、yyyy-mm-dd 日期，以及标准的美国州名或代码。用其他语言的电子表格导出的文件，可能带有翻译过的表头，这些表头无法识别：请把它们改回上面的英文表头。对于 AtlasDays 完全无法读取的文件，导入屏幕上的用 AI 创建 CSV会提供一段转换用的提示词。
