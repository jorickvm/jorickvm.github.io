ビザ申請用の旅行履歴テンプレート（無料CSV）

国での滞在ごとに1行を使い、ISO形式の日付を記入する無料の旅行履歴シートです。Excel、Numbers、Googleスプレッドシートで開け、DS-160、英国、カナダの申請書に転記でき、AtlasDaysにも直接インポートできます。

最終確認：2026年9月

要点：テンプレートをダウンロードし、1つの国での滞在につき1行追加します。すべての日付はYYYY-MM-DD形式にします。列はCountry、State、Start Date、End Date、Purpose、Notesで、AtlasDaysがインポートする列と同じです。申請書に旅行履歴が必要になったら、対象期間の行に絞って転記します。同じファイルのAtlasDaysへのインポートは無料で、アプリが国ごとの滞在日数を数えます。

各列に入力する内容

Country
国名の英語表記（Portugal、United Kingdom）または2文字のコード（PT、GB）。すべての行に必須です。
State
米国への旅行のみ。州名、郵便用の略号（NY）、ISOコード（US-NY）のいずれか。ほかの国では空欄にします。
Start Date
その国に到着した日。
End Date
その国を出た日。日帰りの場合は開始日を繰り返します。現在も滞在中の場合だけ空欄にします。
Purpose
Personal、Business、Study、Transitのいずれか。Transitは空港内にとどまり、その国に入国しなかった場合だけ使います。
Notes
申請書で必要になり得るその他の情報。滞在都市（カナダの訪問者ビザ申請書では必要）、申請書独自の訪問目的の表現（「姉妹を訪問」など）、日付の根拠（パスポートのスタンプ、搭乗券、予約メール）、推定日付であることなどを記します。

サンプル行をファイルに入れていないのは、消し忘れた行が実際の旅行としてインポートされるためです。入力後のファイルは次のようになります。

不確かな日付を含めた記入方法

正確な日付はすべてYYYY-MM-DD形式にします。並べ替えが正しくでき、日月と月日の取り違えもなく、AtlasDaysがインポートする形式でもあります。1行の2つの日付は同じ精度にします。どちらも正確な日付か、年のみです。

  • 日付が分かる場合。その日付を入力し、根拠をNotesに記します。
  • ある程度絞れる場合。証拠から支持できる最善の推定日を通常の日付として入力し、Notesに「estimated」と根拠（「結婚式の翌日、14日か15日」など）を記します。日付セルに「~」や「approx.」を入れると日付として読めなくなり、AtlasDaysはインポート時にその行を拒否します。
  • 年しか分からない場合。4桁の年をStart Dateに入れ、End Dateは空欄にします（滞在が翌年まで続いた場合は後の年を入れても構いません）。正直な記録ですが、多くの申請書では少なくとも月が必要です。こうした行は調べて埋めるべき空白として扱ってください。

表計算アプリでの落とし穴があります。Excelなどは2025-03-03を日付に変換し、03/03/2025など地域設定の形式で保存し直す場合があります。どこかにインポートする前に日付列が引き続きYYYY-MM-DDと表示されるか確認し、違う場合はその形式かプレーンテキストに設定してください。

1旅行につき1行ではなく、1滞在につき1行

1行は1つの国での連続した滞在を表します。2か国を回った旅行は2行で、国境を越えた日は両方の行に入ります。上の例の3月10日にはポルトガルとスペインの両方にいたためです。この形式は行をまとめやすく、後から分割しにくい申請書にも対応できます。

1回の旅行、3種類の申請書。英国のビザで暮らし、2025年3月3日にリスボンへ飛び、3月10日に列車でマドリードへ行き、16日に帰国します。テンプレートには、Portugal 2025-03-03から2025-03-10とSpain 2025-03-10から2025-03-16の2行を記します。

カナダの訪問者ビザではSchedule 1に国ごとの年月が必要なので、両方を2025-03から2025-03として転記し、Notesのリスボンとマドリードを滞在地に使います。英国の帰化ではForm ANに英国からの不在が必要なので、2行を1つにまとめ、3月3日に出国、16日に帰国、国外で過ごした丸1日は3月4日から15日の12日とします。シェンゲンビザの申請書は旅行一覧そのものを求めません。

複数行を1回の不在にまとめるときは、両端のフライトを確認してください。夜間に出発した場合、居住国を出た日はファイルの最初の到着日より1日早いことがあります。

申請書への転記

  1. 対象期間の一覧表で、申請書が何年前まで求めるかを調べます。DS-160は5年、英国の訪問者ビザとカナダの永住申請は最大10年、市民権は資格取得期間全体です。
  2. Start Dateで並べ替え、対象期間より前に終わった行を非表示にします。
  3. 推定日または年のみと記した行は、証拠で確認できる範囲で詳しくします。
  4. 申請書の求める形式に合わせます。ビザなら国ごと、市民権なら不在ごとに1行、年月だけでよい場合はその精度で記入します。
  5. 提出内容の写しを残し、次回の申請を同じ日付から始められるようにします。

AtlasDaysへの無料インポート

テンプレートはAtlasDays独自のインポート列を使っているため、記入したファイルをそのままインポートできます。「設定」→「インポート」→「CSVファイル」で選びます。AtlasDaysは読めない行、重複や重なりの可能性を含む内容を確認画面に表示し、確定するまで何も保存しません。インポートは無料です。その後は旅行を追加するたびに、国ごとの日数、ビザや居住の上限を数えます。

  • Purposeには4つの語のいずれかを使います。AtlasDaysはPersonal、Business、Study、Transitを読み取り、TourismはPersonalとして扱います。それ以外は無視され、目的なしの旅行としてインポートされるため、申請書独自の表現はNotesに残します。
  • Stateは米国のみです。米国以外の行にStateの値があるとエラーになります。
  • 年だけの行は保存されますが日数には入りません。訪問済みの国として記録され、正確な日付を補うまで日数は加算されません。

ファイルがまだない場合、インポート画面には「AIでCSVを作成」のプロンプトもあります。AIアシスタントを使ってメモや旅程をこれらの列に変換できます。AIツールへ貼り付けた内容には、そのツールのプライバシーポリシーが適用されます。

テンプレート以外に確認すること

テンプレートは記録を整理しますが、完全にはしません。5年間の旅行が整った10行だけなら、短い旅行が抜けている可能性があります。申請書自身の指示が常に優先します。申請書別の要件はビザ申請の旅行履歴、スタンプ、メール、写真から空白を埋める方法は旅行履歴の再構成、公的な出入国記録は公的な出入国記録の取得をご覧ください。

AtlasDaysでシートを継続的な滞在日数の集計に

テンプレートを無料でインポートすると、AtlasDaysがiPhone内で非公開に国ごとの日数を数えます。旅行のたびに記録を加えれば、次の申請書が旅行履歴を求めたときも最新の状態です。

AtlasDaysを入手

よくある質問

公的な旅行履歴テンプレートはありますか？

共通の公的テンプレートはありません。カナダのIMM 5257 Schedule 1、IMM 5562、米国のN-400のPart 8のように、申請書自体に旅行の表があるものもあり、提出するのはそれらです。このテンプレートは、各申請書に転記するための手元の記録です。

旅行履歴の日付にはどの形式を使いますか？

手元の記録には、たとえば2025-03-03のようなYYYY-MM-DDを使います。日月と月日を取り違えず、正しく並べ替えられます。申請書の指定するN-400のmm/dd/yyyyやカナダのSchedule 1の年月にも変換できます。

このテンプレートをAtlasDaysにインポートできますか？

はい。見出しがAtlasDaysのCSVインポートと一致するため、ファイルに入力し、「設定」→「インポート」→「CSVファイル」で選べます。インポートは無料です。
