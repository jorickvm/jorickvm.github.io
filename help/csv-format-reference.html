CSV Format Reference

A file needs a country for each row, and dates for the trips that should count toward day totals. AtlasDays finds columns by their English header name, so column order does not matter, and it recognizes the names other travel apps use. Steps for importing are in CSV Import.

Columns

Recommended header row for a file you write yourself: Country,State,Start Date,End Date,Purpose,Notes. Header names are not case-sensitive, and an underscore counts as a space. Unrecognized columns, such as Days, are ignored. If two columns mean the same thing, the first one is used, except that a column named exactly Purpose always wins.

Country
Also read from Countries, Country Name, Country/Region, Nation, Place, or Destination. Country name in English or in the app language, ISO two-letter code, or a common alias such as USA, UK, or Holland. An alias that could mean two places is rejected.
Country Code
Also read from ISO, ISO Code, ISO2, Alpha-2, Code, or CC. A two-letter code. When a file has both, the code is used and the name ignored.
State
Also read from US State, State/Province, Province, Region, or Subdivision. United States trips only: state name, two-letter postal abbreviation, or ISO code such as US-CA. District of Columbia is accepted.
Start Date
Also read from Start, Arrival, Arrival Date, Entry, Date From, Begin, Check-in, and similar names. See Date formats below.
End Date
Also read from End, Departure, Departure Date, Exit, Date To, Until, Check-out, and similar names. Empty means ongoing (exact start) or the same year (year start).
Purpose
Also read from Reason, Type, Trip Type, Category, or Visit Type. Personal, Business, Study, or Transit, not case-sensitive. Combine non-Transit values with commas inside quotes, such as "Business, Personal", or with ; or /. Common words are mapped: Work is Business, Holiday or Vacation is Personal, School is Study, Layover is Transit. Other values are kept as a Purpose: line in the trip's notes.
Notes
Also read from Note, Notes (optional), Comment, Description, Remarks, or Memo. Free text.
City
Also read from Cities or Town. Added to the trip's notes.
Is Current
Also read from Current or Ongoing. Yes, True, or 1 keeps the trip ongoing, whatever its end date says.
Work Days, Personal Days
Used when there is no Purpose column: a trip with only work days becomes Business, with only personal days Personal. A trip with both gets a Mixed purpose note.
Transit
Also read from Layover or Airside. Read only when there is no Purpose column. Yes, Y, True, or 1 marks Transit; No, N, False, 0, or empty does not.
Start Year, End Year
Legacy columns. Four-digit years, used when the date cells hold no year. Cannot be combined with exact dates in the same row.

File layouts

AtlasDays tells three layouts apart by their columns:

  • One row per trip: a country with a start and end date. This is the layout of the template, of an AtlasDays Spreadsheet export, and of most travel apps.
  • One row per day: a Date (or Day) column and a country. Consecutive days in the same country become one trip, and a missing day ends it. If the last day is today or yesterday, the trip is kept ongoing. The header row may be left out when the first row holds a date and a country. For a day in two countries, separate them with a vertical bar, such as France|Germany: both get the day. States and cities can be listed the same way.
  • One row per border crossing: a Date column with From and To countries. Each crossing day counts for both countries, and you stay in the To country until the next crossing. The last stay is kept ongoing. Crossing rows can also be mixed into a day-by-day file.

In a file with no Date column, From and To are read as the start and end dates of a trip.

Besides yyyy-mm-dd, AtlasDays reads:

  • Year first with slashes or dots, such as 2026/03/01 or 2026.03.01. A time after the date, such as 2026-03-01 22:47 or 2026-03-01T22:47:00Z, is ignored.
  • English month names and abbreviations, such as 1 Mar 2026, Mar 1, 2026, or 01-Mar-26.
  • Day first or month first, such as 01/03/2026 or 03/01/2026, with a four-digit or two-digit year. Because 01/03 could be either, AtlasDays reads these only when some date in the file has a day above 12, which shows the order. Otherwise those rows are skipped with Couldn't tell day from month.

A two-digit year is read as 20xx when that is at most 10 years ahead, otherwise as 19xx. Years must fall between 1900 and eight years after the current year. Exact dates and year values cannot be mixed within one row. Year Only trips and trips without dates count toward visited places and the map, but never toward day counts or trackers. A trip without dates can only be created through CSV import.

Special cases

  • US states. Use one row per state when one US visit covered several states. A plain United States row is valid for country-level tracking. A state name in the Country column (California, US-CA) also gives a US trip, and an empty Country with a valid State does the same. Two-letter codes that are also country codes, such as CA, stay countries. Without Pro, state rows import as plain United States trips.
  • Transit. Put Transit in Purpose when you did not enter the country. Transit is exclusive: if it appears with another purpose, only Transit is kept.
  • Delimiter and quoting. Comma, semicolon, and tab are detected from the header row. Quote fields that contain the delimiter or a line break.

Error messages

Rows with an error are listed under Skipped in the preview, grouped by reason with their row numbers, and are not imported. The row number counts the header as row 1.

'<value>' isn't a country name or code
Use an ISO code or an unambiguous country name.
Country is missing
Fill in the country, or delete the row.
Invalid state: '<value>'
Use a US state name, abbreviation, or US-XX code.
State '<value>' is only valid for United States trips
Clear State, or change Country to United States.
Conflicting states
The Country and State cells name different states. Keep one.
Invalid start date / Invalid end date / Invalid date
Use one of the date formats above.
Couldn't tell day from month in '<value>'. Use yyyy-mm-dd.
Write the dates year first, or check that the file's day-first or month-first dates are consistent.
Invalid start year / Invalid end year
Use a four-digit year in range.
Cannot have an end date without a start date
Add a Start Date.
Start date must be before or equal to end date
Swap or correct the dates.
End year must be after or equal to start year
Correct the years.
Cannot have an end year without a start year
Add a start year.
Cannot mix exact dates with approximate year fields
Use either dates or the legacy year columns.
Cannot mix exact start date with year-only end date
Use two dates or two years in one row. The reverse case reads Cannot mix year-only start with exact end date.
Invalid transit value
In the Transit column use Yes/No, True/False, or 1/0.

When no row at all can be imported, the preview does not open. No Trips Found explains why instead, for example AtlasDays couldn't find a country column in this file.

If a value is not recognized

Use an ISO country code, yyyy-mm-dd dates, and a standard US state name or code. A file exported from a spreadsheet in another language may carry translated headers, which are not recognized: rename them to the English headers above. For a file AtlasDays cannot read at all, Build CSV with AI on the import screen gives you a prompt to convert it.
